The problem

Keys leak. A phishing page, malware, a seed phrase in a cloud backup. Once someone has your key, a regular wallet gives them everything — in one transaction.

2FA, guardians and co-signers usually live on servers or with other people. Encrypted Account puts the second factor where the money is: in the contract.

How it works

A PIN the contract checks without ever seeing it

Fully homomorphic encryption lets the contract compare encrypted values. The PIN is never decrypted; only the yes-or-no answer is.

  1. 01

    Set a PIN

    Your browser stretches it with Argon2id and encrypts the fingerprint. The PIN itself never leaves the page.

  2. 02

    Send as usual

    Everyday transfers to addresses you trust stay within your hidden limit. Anything unusual opens a PIN check with a fresh challenge.

  3. 03

    Checked under FHE

    The contract compares encrypted values and records the attempt before anyone learns the result.

  4. 04

    Only yes or no comes out

    Zama's threshold network decrypts a single bit. Correct: the transfer goes. Wrong: nothing moves, and the next try waits longer.

Every guess counts

Attempts are written on-chain before the result is decrypted. From the third wrong guess, the wait grows from 15 minutes up to 7 days.

An encrypted address book

30 recipients and 10 spenders, stored as ciphertext. The key holder can't read them.

An escape without FHE

If your key leaks, start an escape: after a delay, funds can only go to your backup address. Even if the thief starts it.

fp = argon2id(pin, 64 MiB)
ok = FHE.eq(enc(fp + c), stored + c)
// only ok is ever decrypted

No 2FA server

The second factor is not a code from an app or a server. Its state and its rules live in the contract.
